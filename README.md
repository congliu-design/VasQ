# 🧬 About VasQ

**VasQ** is a custom AI-powered chat system designed to support complex biomedical reasoning, particularly around vascular biology and drug delivery in the human brain. It is built on the OpenAI API (GPT-4o by default) and orchestrates several data sources behind a single conversational interface:

- **Human brain vascular snRNA-seq atlas**: Region-, cell-class–, and cell-type–specific gene expression from a human vascular single-nucleus RNA-seq atlas generated by the Brain Resilience Laboratory at Stanford University. VasQ exposes this through **two complementary backends** — a ranked **marker-gene** table and a **log-normalized expression matrix** (see below).
- **SPOKE knowledge graph (KG-RAG)**: A biomedical knowledge graph of curated biological relationships (genes, proteins, drugs, diseases, etc.), served by a retrieval-augmented generation (RAG) system that injects structured, provenance-cited context into the model.
- **Google Vertex AI Search**: Live web/literature search (via Discovery Engine) to retrieve up-to-date biomedical information from a curated web corpus.

These components work together to support **multi-hop investigations** across gene expression, disease associations, and pharmacological mechanisms. For example, users can query transporters enriched in disease-relevant brain regions and trace their roles in blood-brain barrier (BBB) transport and drug uptake.

## Key capabilities

- **Natural language querying** of transcriptomic data across **41 brain regions** and **23 cell types** (grouped into 10 broader cell classes and 10 region layers), for both sexes.
- **Two expression backends**, automatically selected per query:
  - `gene_expression` — ranked **marker genes** per cell type and region.
  - `matrix_expression` — **log-normalized mean expression** and percent-expressing statistics computed directly from the sparse highly-variable-gene (HVG) matrix (~443k nuclei × ~15,000 genes), with optional filtering by region, region layer, cell class, cell type, and sex.
- **Dynamic knowledge graph retrieval** to surface disease- and mechanism-related insights from SPOKE, with source provenance.
- **Web/literature search integration** via Google Vertex AI Search for real-time external references.
- **Interactive Plotly charts** returned alongside text answers for expression queries.
- **Intelligent tool routing** — VasQ combines heuristic routing, OpenAI function-calling, and a final synthesis step to answer directly without exposing internal tooling.
- **Zero model training required** — fully operational via API keys and Docker.

VasQ is ideal for generating hypotheses around **BBB-targeted therapeutics**, understanding **region-specific vascular biology**, and identifying **molecular pathways** for rational drug design.

# 🏗️ Architecture

VasQ runs as **two services**:

| Service | Stack | Role |
|---------|-------|------|
| **`vasq/`** | Django 4.2 + django-ninja, WhiteNoise, Plotly.js | Web UI, chat orchestration, expression backends, web search, tool routing & synthesis. |
| **`kg_rag/`** | Flask + KG-RAG (LangChain, ChromaDB, sentence-transformers) | SPOKE knowledge-graph RAG service, queried over HTTP by the Django app. |

**Request flow:** the browser calls the Django chat endpoint (`/vasq/chat/`), which routes the query to the appropriate tool(s) and asks the model to synthesize a final answer:

1. **Explicit web/literature intent** (e.g. "find papers", "search PubMed") → **Vertex AI Search**.
2. **Top-gene / marker questions** → `gene_expression` (ranked marker table).
3. **Expression-value questions** → `matrix_expression` (log-normalized matrix).
4. **Otherwise** → OpenAI **function-calling** lets the model choose a tool; plain conversational follow-ups are answered directly.
5. **Disease mentions** → `query_kg_rag` (SPOKE via the Flask service).
6. **Fallback** → Vertex AI Search.

The Django app reaches the KG-RAG service via the `KG_RAG_URL` environment variable (defaults to the internal Railway service URL; use `http://localhost:5005/query` for local Docker Compose).

## Data files

The expression backends read from `vasq/data/`:

| File | Used by | Notes |
|------|---------|-------|
| `expression_markers.csv` | `gene_expression` | Ranked marker genes per cell type / region. **Git LFS–tracked** and large; not committed directly. |
| `region_metadata.csv` | `gene_expression` | Region name/abbreviation aliases and layer metadata. |
| `VasQ_adata_X_sparse.npz` | `matrix_expression` | Sparse (CSR) log-normalized HVG expression matrix. |
| `VasQ_cell_meta_table.csv` | `matrix_expression` | Per-nucleus metadata: region, region layer, cell class, cell type, age at death, sex. |
| `VasQ_gene_names.csv` | `matrix_expression` | Gene symbols aligned to matrix columns (~15,000 HVGs). |

`kg_rag/data/` holds the SPOKE-derived context files and vector store used by the KG-RAG service.

# 🧠 VasQ Setup Guide

Follow the steps below to get your VasQ environment up and running. This project uses Docker and Django, and requires some basic API key setup.

---

## Initial Data Processing (Optional)

`process_c2s.py` processes the raw single-cell data (`.arrow`) files into ranked gene tables using a Cell2Sentence–style aggregation. The processed outputs used at runtime are already included in the project (or pulled via Git LFS), so this step does not need to be repeated. The raw data files are only accessible to lab members.

```bash
python process_c2s.py <arrow_directory> --max_genes 200
```

## 🚀 Initial Setup

**Install Docker Desktop**

1. [Download for your OS →](https://docs.docker.com/desktop/)
2. Open the Docker Desktop app

**Clone this repository**

Open a terminal:

   ```bash
   git clone https://github.com/alinaisakova/VasQ.git

   ```

   ```bash

   git lfs pull
   ```

## 🔑 Add Your Keys

VasQ reads secrets from two environment files: `.env-shared` (Django app) and `kg_rag/.gpt_config.env` (KG-RAG service). Depending on your account type or system setup, these steps may vary slightly.

<details>
<summary>⚗️ <strong>OpenAI API Key (KG-RAG / Flask)</strong></summary>

1. Open the KG-RAG environment file:

   ```bash
   cd kg_rag
   nano .gpt_config.env
   ```

2. Generate your OpenAI API key:

#### Individual Users

- Create or sign in: [OpenAI Account](https://auth.openai.com/create-account)
- Go to [API Keys](https://platform.openai.com/api-keys)
- Click `+ Create new secret key`
- Name it, keep **Default project** and **All permissions**
- Click `Create secret key` and copy the key

#### Organization Accounts

- Log in to your org account
- Visit [Organization API Keys](https://platform.openai.com/settings/organization/api-keys)
- Click `+ Create new secret key`
- Name it, choose the appropriate project, keep **All permissions**
- Click `Create secret key` and copy the key

3. Paste the key into `.gpt_config.env` after `API_KEY=`
4. Copy the key to your clipboard for use in the Django environment file
5. Save: `Ctrl + X`, `Y`, `Enter`

</details>

---

<details>
<summary>🧠 <strong>OpenAI API Key (Django)</strong></summary>

<details>
<summary>🔍 <strong>Google Vertex AI Search (web/literature search)</strong></summary>

VasQ's web search is powered by **Google Vertex AI Search (Discovery Engine)**. You'll need a Google Cloud project with a Vertex AI Search app and a service account.

1. In [Google Cloud Console](https://console.cloud.google.com), create/select a project and enable the **Vertex AI Search / Discovery Engine API**.
2. Create a **Search app** (engine) and note its **Engine ID** and **location** (e.g. `global`).
3. Create a **service account** with access to Discovery Engine and download its JSON key.
4. Add the following to `.env-shared`:

   ```bash
   VERTEX_PROJECT_ID=your_gcp_project_id
   VERTEX_ENGINE_ID=your_search_engine_id
   VERTEX_LOCATION=global
   VERTEX_SERVING_CONFIG=default_search
   GCP_SERVICE_ACCOUNT_JSON={...paste the full service-account JSON on one line...}
   ```

</details>

<details>

```bash
GOOGLE_API_KEY=your_google_api_key

```

- [Google Custom Search API](https://console.cloud.google.com/marketplace/product/google/customsearch.googleapis.com) → enable, then create an **API key** under **Credentials** and restrict it to the Custom Search API.
- Create a search engine in the [Programmable Search Control Panel](https://programmablesearchengine.google.com/controlpanel/all) (search the entire web) and copy its **Search engine ID**.

## 🛠️ Launch the Application (Local)

1. Build and run both services with Docker Compose:

   ```bash
   cd vasq
   docker-compose build --no-cache
   docker-compose up
   ```

   This starts the Django web app on port **8000** and the KG-RAG Flask service on port **5005**. If a pop-up window appears, click `Allow`.

   > When running locally, point the app at the local KG-RAG service by setting `KG_RAG_URL=http://kg_rag:5005/query` (the compose service name) in `.env-shared`.

2. Open your browser and visit:
   [http://127.0.0.1:8000/vasq/](http://127.0.0.1:8000/vasq/)

## ☁️ Deployment (Railway)

VasQ is deployed on [Railway](https://railway.app) as two services, each built from its own `Dockerfile.railway` and served with **gunicorn**:

- **`vasq/Dockerfile.railway`** → Django app (`gunicorn newui.wsgi:application`), served publicly (e.g. `https://vasq.up.railway.app`).
- **`kg_rag/Dockerfile.railway`** → KG-RAG Flask app (`gunicorn api:app`), reached by the Django service over Railway's private network.

Configuration notes:

- Allowed hosts / CSRF origins are set in [`vasq/newui/settings.py`](vasq/newui/settings.py); add your deployment domain there.
- Set `KG_RAG_URL` on the Django service to the KG-RAG service's internal URL (e.g. `http://kg-rag.railway.internal:8080/query`).
- Provide all API keys and Vertex AI variables as Railway environment variables.
